# ARM workspace free tier — Phase 1 review

**Status:** In progress. ARM64 builds, tests, signing, uploads, Azure OIDC and scoped RBAC pass. Azure Image Builder failed before allocating a build VM in two attempts. The pipeline now uses an isolated native ARM VM and the same signed artifact verifier and gallery. VM workload acceptance remains pending. **Date:** 2026-10-04. **Scope:** Gen 2 workspace runtime only.

See the [Phase 0 decision record](./arm-workspace-free-tier-phase-0.md). No production runtime or web deployment was changed. Publishing commits use `[skip ci]` to avoid the existing automatic production deployment workflows; the isolated ARM image workflow is dispatched manually.

## Decision

Build a standalone Ubuntu 24.04 ARM64 VM image for one workspace per Azure VM. `Standard_Dps_v6` does not expose nested virtualization, so it cannot host the existing Firecracker guest. Keep the x86 Firecracker image, gallery definition, and deployment flow separate and unchanged. The isolated candidate uses its own image definition, resource group, artifact storage, and manual GitHub Actions workflow.

The new `codev-guestd` TCP mode is opt-in and refuses any non-loopback bind address. The default remains the existing Firecracker vsock listener. The image starts the guest daemon and Superset host on loopback only, creates bridge credentials per VM at first boot, and does not include a tunnel credential or member/GitHub credential. Image provisioning uses a temporary Azure CLI configuration directory and deletes it on exit so managed-identity token caches are not baked into the image. Do not route this unauthenticated local API through Cloudflare Tunnel until request authentication and workspace-generation checks are implemented in the later bridge phase.

## Changes prepared

- `services/orchestrator/src/bin/guestd.rs` retains vsock by default and adds an opt-in TCP listener with a loopback-only address check.
- `infra/runtime/scripts/build-arm-workspace-runtime.sh` creates a clean source copy, builds native ARM64 Superset and guestd artifacts, runs the Rust tests, checks ELF architecture, and writes a versioned manifest and checksums. It excludes existing ignored `node_modules` and Rust `target` directories.
- `infra/runtime/scripts/provision-arm-workspace-image.sh` describes the credential-free VM image, systemd units, durable LUN 0 mount, private `codev-shell` account, per-VM local bridge secrets, and loopback services.
- `infra/azure/arm-workspace-image-builder.bicep` defines the separate ARM64 gallery and pinned Ubuntu source. The native VM validation checks Superset and guestd before gallery publication.
- `infra/azure/arm-workspace-artifacts.bicep`, `prepare-arm-workspace-artifacts.sh`, and `build-arm-workspace-image.sh` define private release storage and the isolated candidate build path.
- `.github/workflows/build-arm-workspace-image-azure.yml` is manual-only and restricted to `main`. It builds on a native ARM64 GitHub runner, keylessly signs each runtime artifact with Sigstore, uploads immutable versioned blobs, then provisions, validates, and generalizes an isolated native builder VM before gallery publication. The image provisioner verifies each signature bundle against this workflow identity before installing artifacts. Cosign 3.1.3 is pinned by SHA-256 (`c5d324e091826b0d7a78eb16fef316450b4eb9aaec045611c08ba06f5e73220a`).

Keyless blob verification uses the bundle with workflow identity and OIDC issuer checks as described in [Cosign's verify-blob documentation](https://github.com/sigstore/cosign/blob/main/doc/cosign_verify-blob.md). The public Sigstore transparency log will expose artifact digests and the workflow identity when the manual workflow runs; it will not contain workspace or provider credentials.

## Acceptance criteria

Phase 1 is complete only when all of the following have recorded evidence:

1. The manual `Build ARM workspace image (Azure)` workflow completes on `main`; its native ARM64 build and guestd tests pass without new warnings.
2. Every runtime artifact has a checksum and a valid Sigstore bundle matching the exact repository, workflow file, `main` ref, and GitHub OIDC issuer. The native builder VM verifies the signatures before extracting or executing the artifacts.
3. The native candidate build publishes a new immutable version under `codev-workspace-arm64` in the isolated candidate gallery, from pinned Canonical Ubuntu `24.04.202609040`. The existing `codev-host` definition and production image deployment remain untouched.
4. A deny-inbound, unzoned `Standard_D2ps_v6` VM boots that candidate with an OS disk at or below the modeled 32 GiB E4 tier. A new 16 GiB disk at LUN 0 mounts at `/workspace`; the guest and Superset services become healthy on loopback. Reboot and VM replacement preserve the workspace disk contents.
5. On that VM, terminal/file/Git/worktree/upload smoke tests pass; Codex and Claude each complete a turn using the control-plane credential path. No credentials are found in image files, VM metadata, logs, or the terminal account.
6. The common dependency compatibility list distinguishes ARM64-supported dependencies from x86-only dependencies, and unsupported project dependencies produce an explicit architecture error.

All six criteria gate Phase 1 completion and Phase 2 readiness.

## Native builder retry decision (2026-10-04)

Runs [37182347425](https://github.com/CoDevOrg/CoDev/actions/runs/37182347425) and [37184023742](https://github.com/CoDevOrg/CoDev/actions/runs/37184023742) failed after approximately eleven minutes creating an Image Builder template, both returning `ServerError / InternalOperationError`. Neither allocated a build VM; the staging resource groups contain no resources. The second attempt used the source-compatible `TrustedLaunchSupported` definition and successfully read and checksum-verified the private provision script before submission. Run [37183739159](https://github.com/CoDevOrg/CoDev/actions/runs/37183739159) separately exposed Azure's inability to update the existing empty image definition; it was recreated after verifying there were no published versions.

Use a native, deny-inbound `Standard_D4ps_v6` builder VM instead of the managed Image Builder service. GitHub Actions provisions and validates through Azure Run Command, generalizes it, and publishes from the VM directly to the same isolated gallery. The source image pin, native artifact build, exact-workflow Sigstore checks, immutable release/version requirements, and VM-level acceptance gates are retained. Run Command receives credential-free source only. No product bridge, Phase 2 implementation, or production deployment is included.

The local Claude connection reports `Credit balance is too low` on a real minimal turn. A usable funded connection is required for the final Claude acceptance test; sign-in status alone is insufficient evidence.

The first native attempt, [37185049233](https://github.com/CoDevOrg/CoDev/actions/runs/37185049233), surfaced a concrete Compute validation error: explicitly setting `securityType: Standard` requires the subscription-level `UseStandardSecurityType` feature, which is not registered. The template now leaves the optional security profile unset and enables accelerated networking required by Dpsv6. This avoids changing subscription feature registrations. The failed attempt's temporary network resources were cleaned up.

[Run 37185325505](https://github.com/CoDevOrg/CoDev/actions/runs/37185325505) successfully allocated the native ARM builder with a 30 GiB OS disk. In-VM installation, exact-workflow Sigstore verification, CLI versions, Superset/PTY health, and guestd loopback validation completed at 07:24:24 UTC (`CODEV_ARM_IMAGE_VALIDATED`). The next Azure Run Command stalled because `waagent -deprovision+user` removes the agent state that must report its own completion. The diagnostic run was stopped and its temporary VM/networking cleaned up. Generalization now runs over host-key-pinned SSH restricted to the runner's IPv4, then removes that temporary inbound rule. No runtime API is exposed.

The Rust runtime now reports `Unsupported executable architecture` with the running Linux architecture and rebuild guidance for incompatible executables. All 70 library tests and two guestd tests pass natively on ARM64 Linux in Apple `container`. The native CI build additionally runs the architecture-error tests.
